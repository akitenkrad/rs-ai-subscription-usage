# アーキテクチャ

## 2 つのプロバイダを合算しない

最上位の分割はプロバイダで，それが末端まで貫かれています．走査も state も出力ディレクトリも利用制限の記録も別々で，Claude と Codex を 1 つの数字に足す箇所はどこにもありません．

これは実装上の都合ではありません．2 つのサブスクリプションは**別の母数**で計られます — Claude の週次制限はモデルとキャッシュ種別で重み付けした API 換算額，Codex はプランによって長さの変わる枠に対する消化率 — そして 1 トークンが意味する金額も違います．合算した «43% 消化» や合計金額は，何の判断にも使えない数字です．合算しにくい構造にしてあるのは意図的です．

## common 層と provider 層

```
src/
├── cli.rs         clap の定義: provider → 任意の操作 + フラグ
├── main.rs        provider への振り分け，[ERROR] 表示，exit 1
├── config.rs      パスを 1 か所に集約．HOME と OBSIDIAN_VAULT
├── common/        プロバイダ間で共有するもの
│   ├── aggregation.rs   UsageRecord, TokenUsage, Scope, CacheClass
│   ├── state.rs         増分状態，版の管理と移行
│   ├── atomic_write.rs  一時ファイルへ書いてから rename
│   ├── date.rs          固定オフセット +09:00
│   ├── discovery.rs     *.jsonl の再帰列挙
│   └── jsonl.rs         行の読み取り
├── claude/        transcript，価格表，週の窓，利用制限 API
└── codex/         セッションログ，利用制限の観測値
```

`common` が持つのは語彙と仕組みです — 利用記録とは何か，増分更新はどう動くか，ファイルをどう安全に書くか．どちらのログ形式も知りません．

provider 側は固有のものをすべて抱えます．そして**両者は非対称です**．Claude には価格表と週の窓のモデルと認証付きの利用制限 API があり，Codex には価格も API も無い代わりに，自身のログの中に利用制限の観測値が散らばっています．この差を共通の抽象で覆っても，違いが見えなくなるだけです．

パスを知っているのは `config.rs` だけです．他のどこもパスを組み立てないので，出力先や state の置き場所を変えるのは 1 ファイルの変更で済み，テストは `HOME` と `OBSIDIAN_VAULT` を一時ディレクトリへ向けるだけで完全に隔離された実行を得られます．

## 増分走査と冪等性

再走査には副作用が無くてはなりません．ジョブは日次と毎時で重なるデータの上を回り，その合間に手で実行することもあります．

これを 2 つの仕組みで担保しています．

**`mtime` + サイズによる新鮮さの判定．** `state.json` の各エントリは，入力ファイルの更新時刻とサイズを，そこから得た集計と一緒に持ちます．変わっていないファイルは読み飛ばします．`--all` はこの判定を無効にし，実在するものをすべて読み直します．

**位置ではなく «同一性» による重複排除．** Claude の transcript では `message.id`，Codex のログでは `response_id` で重複を落とします．Codex の利用制限の観測値は JSONL へ追記する時点で `observed_at` によって落とすので，`--all` の全走査を回しても行は 1 つも増えません．同一性の判定を書き込みの側に置いてあるため，冪等性は state が無事かどうかに依存しません．

読み飛ばしには 1 つだけ意図的な例外があります．利用制限の収集は集計の後から足した機能なので，それ以前に走査済みのファイルは，観測値を一度も集めないまま «新鮮» の印だけが付いていました — そして読み飛ばしたファイルからは何も取れません．そこで state の各エントリは `limits_harvested` の印を持ち，これを持たないエントリはちょうど 1 回だけ読み直します．この印が無かったとき，実際に 985 点あった観測のうち長期記録に入ったのは 321 点だけでした（2026-09-10 実測）．元のログは刈られるので，取りこぼした分は復元できません．

## state はキャッシュではなく記録そのもの

Claude Code は `~/.claude/projects` の transcript を約 30 日で削除し，Codex も `~/.codex/sessions` を刈ります．したがって:

- 入力から再計算できるのは直近 30 日ぶんだけです．それより古い分は `state.json` の中にしか存在しません．
- 入力ファイルが消えたときは state のエントリを捨てずに `missing` の印を付け，月次の出力に足し続けます．`--forget-missing` はそれを捨てる操作で，取り消せません．
- 置き場所は `~/.cache/` ではなく `~/.local/share/` です．キャッシュ用のディレクトリは OS が消して構わない場所だからです．
- 書き込みはすべて一時ファイル + rename です．書き込み中に落ちて履歴が飛ぶことがあってはなりません．
- `state.json` と `limits.jsonl` はどちらもバックアップの対象です．

`state.json` には版があります．より細かいデータが要る版上げ（日単位 → 時間単位，その後に人の発話数の追加）では，実在する transcript を全部読み直します．そして «既に消えた分は埋められない» ことが移行の説明に明記されています — 新しく足した次元に依存する数字を，古い期間について語ってはいけません．

## 何を利用量として数えるか

### Codex は同じ利用量を 2 回書く

Codex は 1 応答の利用量を 2 か所に記録します．`token_usage_record` の行と，`event_msg` の `token_count` 行に入る `last_token_usage` です．**課金量として数えるのは前者だけです** — 両方足すと二重計上になります．後者はまったく別の用途に使います．その `rate_limits` が利用制限の観測値の出どころであり，トークン数の方はコンテキスト窓の観測です．

### トークンには包含関係がある

`cached_input ⊆ input`，`reasoning_output ⊆ output` です．原始値は報告されたまま保存し，差（`non_cached_input`，`normal_output`）は表示のために飽和減算で出します．導出値を元の原始値に足すと，同じトークンを 2 回数えます．入力データ側で包含関係が壊れている場合（`cached_input` が `input` を超える等）は，値を丸め込まずそのまま保持し，異常として記録します．

### 金額は参考額

金額は «同じ通信を公開されている API 価格で流したらいくらか» です．請求書ではありません（サブスクリプションは定額です）．価格はバイナリからではなく実行時に `pricing.json` から読み，価格の無いモデルは `0` ではなく `null` になります — «無料» と «不明» の区別はダッシュボードまで届ける必要があります．

### 利用制限は «観測» であって «推定» ではない

消化率をトークン数から導く箇所はどこにもありません．Codex の値は自身のログの `rate_limits` から，Claude の値は `GET https://api.anthropic.com/api/oauth/usage`（`/usage` 画面が読んでいるのと同じエンドポイント）から来ます．どちらもアカウント全体の値で（Claude 側は claude.ai / Cowork の分を含みます），CLI の利用分だけを取り出すことはできません．この但し書きは両方の出力ファイルに `note` として入れてあり，数字と一緒に運ばれます．

唯一，読むのではなく逆算している場所（Claude の `_windows.json`）は，自分の限界について明示的です．手元から見えるのは Claude Code の分だけなので，計算した % は**下限**であり，本当の値は «直近に読んだ観測値からの比» による**幅**として出します．1 つの確信ありげな数字にはしません．

Codex 側で対応する落とし穴 — `primary` / `secondary` は «席» であって，枠の長さはプランによって変わるので，CLI は `window_minutes` を記録するだけで枠にラベルを付けない — は [出力ファイル](output.ja.md) に書いてあります．

## 失敗したときの方針

不完全なデータは無いよりましですが，黙って失敗するのは許されません．

- JSON として読めない行は数えて読み飛ばし，ファイルも実行も続けます．件数と該当ファイルは報告します．
- 利用制限の JSONL の 1 行が壊れていても，他の観測点は無効になりません．
- `limit.json` が無いのはエラーではありません（基準が無いので `_windows.json` を飛ばすだけです）．一方で壊れている / 版が違うのはエラーです — でないと «未設定» と «書き間違い» が見分けられません．
- 価格表が無いのは**エラーです**．そうしないと，1 か月ぶんの `null` の金額が «価格表の穴» のように見えてしまいます．
- 素の `codex` 実行中の利用制限の更新の失敗は警告です．月次 JSON は既に書けており，それを壊してはいけません．`codex limits` では同じ失敗がエラーになります．
- エラーメッセージにキーチェーンの中身やアクセストークンを載せません．launchd のジョブは stderr をログファイルに残すためです．
